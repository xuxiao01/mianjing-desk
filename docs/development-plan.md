# 登录与真实 API 接入验收

前后端功能分支完成代码和本地联调后，先由后端 Actions 发布独立服务并验证，再合并前端 main 触发静态部署。其他项目未提交改动不参与发布。

## 实现

- 邮箱／密码登录及一小时只读游客入口，管理员以服务端配置 ID 2 校验。
- `/me` 决定身份；独立 Token 存储，刷新、新标签页、跨页退出及 401 返回登录。
- 服务端分页／详情／公司库读取，新增／编辑题目、公司标签、状态、次数、快速记录、内容编辑及直接删除。
- 管理员维护，游客只读；云端概况取代备份、恢复、重置。
- 保留紧凑列表、高亮、实心公司标签和沉浸阅读。旧本地数据不读取、不迁移、不删除。

## 自动验证

```sh
pnpm build
pnpm lint
pnpm format:check
pnpm test
```

覆盖登录失败、账号拒绝、游客权限、会话同步、过期退出、站内返回地址、服务端查询和字段契约、保存失败重试、来源完整性、直接删除确认、分页校正及原有回归用例。

后端真实 PostgreSQL 测试验证权限、独立游客密钥与用途、时效、两个新增入口、搜索分页、标签、计数、来源、公司配置、删除和事务回滚。只使用明确指定的本机独立空测试数据库。

## 浏览器验收

使用虚构测试账号和独立本地端口；检查 1440×900 和 430px：游客进入及原详情返回、其他账号拒绝、管理员表单、公司选择及管理往返草稿、问法单内容编辑、删除确认取消、云端概况、新标签页会话复用、跨标签退出及 API 401 跳转。验收不提交草稿或修改生产记录。

## 后续上线顺序

先审核迁移、配置管理员与独立游客密钥并上线后端，验证身份和接口；再合并前端，由现有 GitHub Actions 发布。详细说明见 [本地联调与上线边界](login-api.md)。
